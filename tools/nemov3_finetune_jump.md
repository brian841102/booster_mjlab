# Nemov3 训练调优记录：滑冰中按键跳跃（nemov3_velocity_amp_jump）

Nemov3（轮足人形）在 booster_mjlab 里做「滑冰前进中按一个键跳起来、落地后继续滑冰」训练的实验历程。起点是实机部署用的 Exp 90（转弯 + 固定头腰 + 部署 PD + 合并延迟 + 躯干质量 + 后退指令，见 `tools/nemov3_finetune.md`）。
**约定：每做一次实验，就在「实验日志」末尾追加一节，写清楚改了什么、结果怎样、有用还是没用，并同步更新「有用 / 没用速查表」；实验设置在启动时写、仿真评估结果在评估完成时写、实机结论在分析完 bag 时写。**

## 设计（J01 起）

### 1. 按键 = 一个命令项

- `mdp/jump.py: JumpCommand`（命令名 `jump`）：按下后 `duration` = **0.6 s** 内策略看到 `(flag, phase)` = (1, t / 0.6)，之后回到 (0, 0)。0.6 s 大约够下蹲、蹬地、5 cm 的约 0.2 s 腾空和落地。
- 观测：`jump_command` 接在 actor / critic 观测的**末尾**（actor 69 → 71 维、critic 80 → 82 维），所以 Exp 90 的检查点只要在第一层补两列就能用。
- 训练中的触发：只在前进指令 ≥ **0.3 m/s** 时（"前进过程中"）随机触发；准备好后平均 **2.5 s** 一次，窗口结束后冷却 **1 s**。转弯指令不限制。
- play 不自动触发：评估 / 录像脚本调用 `JumpCommand.trigger()` 按键。
- 部署端：runner 的指令里已有 `jump_flag` / `jump_dur` 字段（2026-10-23 runner 日志：`cmd=[vx ... h=0.160 jump_flag=0.000 jump_dur=0.000]`），含义与时序待上机核对；若不一致，再改观测或在部署端换算成 (flag, phase)。
- 镜像：`jump_command` 左右对称，镜像规则 (1, 1)（`nemov3_symmetry.py`）。

### 2. 跳跃奖励（`JUMP_WEIGHTS`，env_cfgs.py）

和其他任务项一样，在 AMP runner 里乘 (1 − 风格权重 0.7) = 0.3。

| 奖励项 | 权重 | 内容 |
|---|---|---|
| `jump_air_height` | +10 | 窗口内两轮同时离地时，付 min(较低轮离地高度 / **5 cm**, 1)：高度到 5 cm 就饱和，不鼓励再高 |
| `jump_takeoff_velocity` | +2 | 窗口前一半，躯干向上速度（截到 0~1.2 m/s）：从"完全不会跳"开始的起跳引导 |
| `jump_height_excess` | −2 | 任何时候轮子离地超过 **9 cm** 的部分 / 2 cm：防止跳太高 |
| `hop_outside_jump` | −2 | 窗口和恢复期之外，两轮同时离地 **> 1 cm**：防止没按键乱跳（1 cm 门槛见速查表） |

Exp 90 原有的奖励全部保留：速度跟踪在跳跃中照常生效（要求跳起来时仍保持前进），`upright` / 角速度 / 动作变化率等也照常。

### 3. AMP 风格奖励的屏蔽

- 参考动作（三个滑冰 clip）里没有跳跃，判别器一定会把跳跃判成"不像"。从按键开始到窗口结束后 **0.6 s**（判别器历史 30 帧 × 20 ms，确保历史里没有跳跃的帧）这段，风格奖励乘 0。
- 实现：`JumpCommand` 每步写 `env.amp_style_mask`（每个环境 0 / 1），`amp_support.py` 有这个属性时把风格奖励乘上它；其他任务没有这个属性，不受影响。
- 判别器本身照常训练（跳跃时的样本也进 policy 缓冲区）。

### 4. 起点：热启动 Exp 90@2999

- `tools/nemov3_tools/jump/widen_checkpoint.py`：把 Exp 90 `model_2999.pt` 的 actor / critic 第一层补两列 0 权重，观测归一化在新两列设均值 0、方差 1，去掉优化器状态，存成 `seed_exp90_2999/model_0.pt`。补完后策略与 Exp 90 完全相同，直到训练改动这两列权重。判别器不变（AMP 特征没变）。
- 训练用 `--agent.resume True --agent.warm-start True`：载入 actor / critic / 判别器，优化器和轮数从 0 开始。
- 种子检查（`jump_eval.py`，32 台）：

  | 速度 | 成功 | 摔倒 | 按键后速度 | 髋摆动 前 / 后 | 非指令两轮无接触（未加门槛前） |
  |---|---|---|---|---|---|
  | 0.6 | 0% | 0 | 0.56 | 0.196 / 0.194 | 0.21 次 / 台 / 分钟 |
  | 1.0 | 0% | 0 | 0.91 | 0.281 / 0.284 | 3.54 |
  | 1.3 | 0% | 0 | 1.17 | 0.342 / 0.339 | 12.08 |

### 5. 物理上是否做得到（粗估）

- 机器人约 14.6 kg；腿部电机仿真力矩上限髋 18 N·m、小腿 20 N·m，部署 PD 腿 kp 50 / kd 0.5。
- 5 cm 离地需要起跳速度约 √(2 × 9.81 × 0.05) ≈ 1.0 m/s、腾空约 0.2 s。粗算两腿可提供的净向上加速度约 4 m/s²，需要约 12 cm 的蹬伸行程——偏紧，但不是不可能（手臂上摆、提前下蹲都能帮忙）。如果 J01 跳不到 5 cm，先看是不是力矩 / 行程不够（饱和在某个高度），再决定改什么。

## 实验日志

### J01：Exp 90 + 跳跃按键（设计见上），热启动 Exp 90@2999，计划 1200 轮（**无效：470 轮完全没探索到跳跃，停止**）
- **实验名**：`j01_exp90_jump5cm`（4096 环境、10 s episode，计划 1200 轮，约 2 s / 轮）
- **起因 / 假设**：先用最直接的设计（按键观测 + 离地高度奖励 + 起跳引导 + 跳跃期间屏蔽 AMP）看策略能不能从 Exp 90 学会跳，以及卡在哪里。
- **改动**：见「设计」第 1~4 节（`mdp/jump.py`、`env_cfgs.py` 的 `jump` 选项、`amp_support.py` 风格屏蔽、`nemov3_symmetry.py`、任务 `...-Backward-Jump`）。
- **命令**：`--env.scene.num-envs 4096 --env.episode-length-s 10.0 --agent.max-iterations 1200 --agent.save-interval 100 --agent.resume True --agent.warm-start True --agent.load-run seed_exp90_2999 --agent.load-checkpoint model_0.pt --agent.experiment-name nemov3_velocity_amp_jump --agent.run-name j01_exp90_jump5cm`
- **启动检查**：热启动日志正常（actor / critic / 判别器载入，优化器从零）；第 2 轮跳跃各项奖励接近 0，与种子"按键无反应"一致；镜像检查 `symmetry_check.py` 19 项全部 OK。
- **监看**：400 / 800 / 1100 轮各跑一次 `jump_eval.py`（32 台）。
- **结果**：@400 奖励曲线（最近 20 轮平均，每回合累计）：`jump_air_height` 0.000、`jump_takeoff_velocity` 0.003、`hop_outside_jump` −0.008；速度跟踪 1.40、转向跟踪 1.29、风格 1.40，回合长度 498（滑冰正常）。`jump_eval` @400：

  | 速度 | 成功 | 摔倒 | 按键后速度 | 髋摆动 前 / 后 | 非指令跳跃 |
  |---|---|---|---|---|---|
  | 0.6 | 0% | 0 | 0.59 | 0.185 / 0.194 | 0.00 |
  | 1.0 | 0% | 0 | 0.95 | 0.264 / 0.270 | 0.00 |
  | 1.3 | 0% | 0 | 1.23 | 0.307 / 0.306 | 0.00 |

  训练停在第 472 轮。
- **原因**：Exp 90 的检查点里，蹬腿要用的四个动作维度（两腿髋 pitch、小腿）的探索噪声只有 0.11 / 0.13 / 0.11 / 0.13（手臂 0.35~0.60），而且噪声在关节、时间步之间独立，几乎不会碰巧做出"两腿同时快速蹬伸"；`jump_air_height` 只在两轮都离地时才给分，起跳速度奖励（+2 × 0.3）也小，所以完全没有学习信号。
- **旁测：开环蹬腿**（`tools/nemov3_tools/jump/jump_feasibility.py`）：站着不动时按固定节奏下蹲（深度 0~0.5、0.1~0.5 s）再一次伸直腿，所有组合都在 3 s 内摔倒（没有平衡控制），倒下前最多瞬间离地 6 cm、0.06 s。**说明不了做不做得到**，只能靠训练回答。
- **结论**：设计本身没问题（滑冰、非指令跳跃都正常），但缺少探索和密集信号。

### J02：J01 + 躯干升高奖励 + 起跳速度权重加大 + 蹬腿探索噪声 0.3，计划 1000 轮（**部分有效：学会按键伸腿顶起躯干，但不下蹲、行程不够，轮子不离地；308 轮停，改 J03**）
- **实验名**：`j02_rise_legstd03`（4096 环境、10 s episode，计划 1000 轮）
- **起因 / 假设**：J01 没有学习信号。给一个"只要腿伸直、躯干升高就有分"的密集奖励，加大起跳速度奖励，同时把蹬腿四个维度的探索噪声提高，应该能先学会快速蹬伸，进而离地。
- **改动**：
  - `mdp/jump.py`：新奖励 `jump_trunk_rise` = 窗口内躯干比按键时升高的量，截到 0~8 cm 再除以 8 cm（`JUMP_TRUNK_RISE_CAP_M`：腿伸直约 3 cm + 5 cm 腾空）；`JumpCommand` 在按键时记录躯干高度 `z0`。
  - 任务 `...-Backward-JumpRise`：`jump_trunk_rise` +10、`jump_takeoff_velocity` 2 → 5，其余同 J01。
  - 种子 `seed_exp90_2999_legstd03`：`widen_checkpoint.py ... 2 0.3`，动作槽 10 / 13 / 14 / 17（两腿髋 pitch、小腿）的探索噪声 0.11~0.13 → 0.3（噪声是可学参数，之后会自己收）。
- **命令**：同 J01，任务换成 `...-Backward-JumpRise-Booster-Nemov3`，`--agent.load-run seed_exp90_2999_legstd03 --agent.run-name j02_rise_legstd03 --agent.max-iterations 1000`。
- **启动检查**：第 2 轮平均动作噪声 0.43（J01 0.38）；`jump_trunk_rise` 0.004、`jump_takeoff_velocity` 0.001（已有信号）。
- **监看**：每 100 轮看奖励曲线，400 / 800 / 999 轮跑 `jump_eval.py`。

## 待办 / 候选方案

- 上机前核对部署端 `jump_flag` / `jump_dur` 的含义与时序，必要时调整观测或部署端换算。
- 若跳不到 5 cm：检查腿部力矩 / 关节行程是否饱和；候选改动——窗口加长、起跳引导加大、动作缩放加大、跳跃期间放宽 `action_rate_l2`。
- 若跳起来但落地摔倒：加落地缓冲（落地时躯干竖直速度 / 姿态）奖励，或延长恢复期。
- 若落地后不再滑冰：检查 AMP 屏蔽的恢复期是否太长 / 太短。
